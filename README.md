Booking API (DRF)

Сделал небольшой backend-проект онлайн записей к специалистам.
Сделал его чтобы разобраться и практиковаться с DRF, бизнес логике и т.д.

Что реализовал:

1. Регистрацию и логин через simple JWT
2. Роли пользователей: (клиент/специалист)
3. Создание бронирований
4. Проверка пересечений записей
5. Проверка рабочего времени специалиста
6. Запрет записи в прошлом
7. Статусы бронирования(ожидает подтверждения, подтверджён, завершён, отменён)
8. Кастомные permissions
9. Пагинацию через limit/offset

Основной стек:

1. Django
2. Django Rest Framework
3. SimpleJWT
4. django-filter

Основные эндпоинты:

1. POST /api/auth/register/ — регистрация
2. POST /api/auth/login/ — получение токенов
3. GET /api/bookings/ — список бронирований
4. POST /api/bookings/ — создать бронь

Тесты:

1. Регистрация пользователя
2. Логин(JWT)
3. Успешное создание брони
4. Создание брони в прошлом(Ошибка)

Что было сложным:

1. Проверка пересечений бронирований через ORM
2. Работа с датой и временем 
3. Написание тестов
4. Написание валидации в сериалайзере для брони

Что я понял: 
1. Как строится API на DRF
2. Как работает авторизация через JWT
3. Как писать и проверять бизнес-логику
